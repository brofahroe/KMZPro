📖 Cara Penggunaan — Opname Aksesoris & Pole

Hitung otomatis kebutuhan aksesoris tiang FTTH (Dead End, Suspension, Slack Hanger, Pole Clamp, Buldog Grip, Joint Closure), panjang Sling Wire, dan panjang Kabel dari file KMZ/KML lalu ekspor menjadi file Excel (.xlsx) siap pakai.

Input: .kmz / .kml (1 s/d 500 file) Maks. Ukuran: 50 MB / file Output: Opname Excel (.xlsx)

🧭 Langkah-Langkah Penggunaan

1

Unggah File KMZ / KML

Tarik & lepaskan satu atau beberapa file .kmz / .kml ke area dropzone, atau klik dropzone untuk memilih file dari perangkat Anda.

2

Sesuaikan Aturan Perhitungan

Pilih Jenis Jaringan (Auto, Distribusi, atau Feeder) dan atur batas sudut tikungan, maks. suspension, jarak crossing pole 9m, kapasitas hasbel, serta opsi Existing Pole.

3

Klik "Proses & Hitung"

Sistem membaca struktur folder KMZ, menghitung aksesoris tiap tiang sepanjang jalur kabel, lalu menampilkan ringkasan KPI, jumlah pole per tipe, dan tabel detail.

4

Filter & Cek Hasil

Gunakan kolom pencarian (berdasarkan POLE ID, tipe pole, cluster, atau remark) dan filter LINE untuk memverifikasi hasil per jalur.

5

Download Opname (.xlsx)

Klik tombol hijau Download Opname (.xlsx) untuk mengunduh laporan Excel berformat rapi lengkap dengan formula SUM otomatis. Jika multi-file, hasil digabung dalam satu workbook.

⚙️ Penjelasan Parameter

  • Jenis Jaringan / Kabel: Auto-Deteksi mengenali Distribusi vs Feeder dari nama kabel (FEEDER, MF, SF, HF, BACKBONE). Mode Distribusi menempatkan Slack di titik FDT/FAT/Slack. Mode Feeder otomatis menambah Slack di ujung kabel, tiap 400 m, dan di titik JC per hasbel.
  • Batas Sudut Tikungan Dead End (°) (default 30°): Tiang dengan sudut belokan melebihi batas ini otomatis diberi 2 Dead End + Pole Clamp.
  • Maks. Suspension Berurutan (default 2): Setelah jumlah Suspension berturut-turut mencapai batas, tiang berikutnya otomatis menjadi titik tarik (2 Dead End + 1 Pole Clamp).
  • Batas Jarak 2 Pole 9m (m) (default 60 m): Dua tiang 9m berurutan dengan jarak kurang dari batas ini dideteksi sebagai crossing → mendapat Dead End + 2 Pole Clamp.
  • Kapasitas 1 Hasbel Feeder (m) (default 3000 m): Khusus Feeder, tiap batas panjang efektif 1 hasbel (termasuk slack & spare 5%) otomatis ditambahkan 1 Joint Closure (JC) + 1 Slack Hanger di tiang terdekat sebelumnya.
  • Sertakan Existing Pole: Jika dicentang, tiang Existing (EP / EPP) ikut dimasukkan dalam perhitungan aksesoris kabel.

📐 Aturan Otomatis & Hasil Output

  • Ujung Kabel: Tiang pertama & terakhir pada setiap jalur kabel otomatis mendapat 1 Dead End + Pole Clamp.
  • Titik FDT / FAT / Slack: Tiang dengan perangkat dalam radius ≤ 10 m otomatis mendapat 2 Dead End + 1 Slack Hanger + Pole Clamp.
  • Jalur Sling Wire: Tiang yang dilalui jalur Sling Wire (≤ 5 m) otomatis ditambah 3 Buldog Grip + 1 Pole Clamp.
  • Klasifikasi Tipe Pole: Otomatis mengelompokkan tiang seperti NP7m2, NP7m3, NP7m4, NP9m4, EP*, dan EPP*.
Integrasi Antar-Tab: Setelah memproses KMZ di Tab ini, data panjang kabel & FAT langsung terkirim ke Tab Hitung Potong Kabel, dan file KMZ pertama bisa langsung dipakai ulang di Tab Edit KMZ, Bersihkan KMZ, dan Split Hasbel lewat tombol "Pakai KMZ dari Tab 1".

💡 Tips & Catatan Penting

  • Pastikan posisi tiang di KMZ menempel pada garis kabel (toleransi snap kabel ke tiang adalah 5 meter) agar aksesoris terhitung akurat.
  • Untuk memproses banyak cluster sekaligus, pilih seluruh file KMZ dalam satu kali unggah — KPI dan file Excel akan otomatis menggabungkan seluruh cluster.
  • Periksa kolom REMARK pada tabel untuk melihat alasan pemasangan aksesoris tiap tiang (misal: Tikungan 45°, Setelah 2 Susp, Crossing 9m, atau JC-1).

🧮 Rumus Perhitungan

Kabel Potong (m) = (Panjang Rute + ((Jumlah FAT/Slack + 1) × Panjang Slack)) × Faktor
  • Tambahan +1 Slack: Menghitung 1 titik slack ekstra untuk terminasi/ujung kabel di luar jumlah FAT atau slack tengah.
  • Tipe Distribusi (FAT): Nilai Jumlah FAT/Slack diambil otomatis dari jumlah titik FAT pada line terkait di file KMZ.
  • Tipe Feeder / SF / MF / HF: Nilai Jumlah Slack otomatis dihitung dengan rumus ⌈Panjang Rute / 400⌉ (dibulatkan ke atas tiap kelipatan 400 meter).

⚙️ Fitur Pintar Tabel

  • Auto-Deteksi Tipe Kabel: Mengetik kata kunci seperti FEEDER, MF, SF, HF, atau SUBFEEDER pada kolom Nama Kabel otomatis mengubah tipe menjadi Feeder dan menghitung ulang jumlah slack.
  • Update Otomatis Rute Feeder: Pada baris bertipe Feeder, mengubah angka Panjang Rute otomatis memperbarui kolom Jumlah Slack.
  • Ringkasan KPI & Pembulatan: Kartu KPI di atas tabel menampilkan total seluruh line beserta total pembulatan atas (Math.ceil) untuk kebutuhan order material.

💡 Tips & Catatan Penting

  • Jika Anda sudah mengunggah file di Tab 1 tetapi belum menekan Proses & Hitung, membuka Tab 2 akan otomatis memicu pemrosesan agar tabel langsung terisi.
  • Gunakan Faktor Pengali 1.05 untuk spare 5%, 1.10 untuk spare 10%, atau 1.00 jika tidak ingin menambahkan spare.

📖 Cara Penggunaan — Edit KMZ (Jalur MF)

Otomatisasi pemindahan folder dan penyesuaian warna/style tiang di dalam file KMZ berdasarkan persinggungan jarak terhadap jalur kabel Main Feeder (MF) atau jalur kabel Cluster — tanpa perlu mengedit tiang satu per satu di Google Earth.

Mode 1: Upgrade Pole 2.5"/3" → 4" Mode 2: Pole MF Bersilangan → Putih Output: File .kmz Siap Buka

🔀 Pilihan Mode Kerja

  • Mode 1 — Cluster + Jalur MF → Upgrade Pole 4":
    Memindahkan tiang NEW POLE 7-2.5 dan NEW POLE 7-3 pada KMZ Cluster yang dilalui jalur kabel MF (jarak ≤ toleransi) ke folder NEW POLE 7-4 serta menyesuaikan style/warnanya. Output: *_EDITED_MF.kmz.

    Mengecek tiang di KMZ Main Feeder (MF) yang bersilangan dengan jalur kabel pada 1 atau beberapa file KMZ Cluster sekaligus. Tiang yang bersilangan dipindahkan ke folder POLE CLUSTER dan diubah warnanya menjadi putih (#ffffff). Output: *_MF_WHITE.kmz.

⚙️ Penjelasan Parameter

  • Toleransi Jarak (meter) (default 5 m): Jarak tegak lurus maksimum antara titik tiang dan garis LineString pembanding agar tiang dianggap dilalui/bersilangan.
  • Warna Pole & "Paksa pakai warna ini": Pada Mode 1, sistem otomatis menyalin style dari folder NEW POLE 7-4 yang sudah ada. Warna pemilih hanya dipakai jika folder 7-4 kosong atau jika checkbox Paksa pakai warna ini dicentang. Pada Mode 2, warna yang dipilih selalu diterapkan.
  • Pakai KMZ dari Tab 1: Pintasan untuk langsung memakai file KMZ dari Tab 1 sebagai KMZ Awal (kotak 1).

🗂️ Perbedaan Aksi

  • Hapus Permanen (Ringankan File): Menghapus folder target beserta seluruh placemark di dalamnya secara permanen dari struktur KML. Sangat cocok untuk memperkecil ukuran file secara drastis sebelum dikirim ke tim lapangan atau dibuka di HP.
  • Sembunyikan (visibility=0): Folder dan placemark tetap disimpan di dalam file, namun properti <visibility>0</visibility> diterapkan sehingga otomatis tidak tercentang saat dibuka di Google Earth dan tetap bisa dinyalakan kembali kapan saja.

📦 Format Output

  • KMZ (.kmz): Format terkompresi ZIP (direkomendasikan). Ukuran file jauh lebih kecil dan mempertahankan aset ikon/gambar bawaan di dalam KMZ asal.
  • KML (.kml): Format XML teks mentah tanpa kompresi. Cocok bila file akan diimpor ke tool GIS/skrip tertentu yang hanya menerima KML.

💡 Tips & Catatan Penting

  • Pencocokan nama folder bersifat tidak peka huruf besar/kecil (misal HP COVER maupun hp cover sama-sama terdeteksi).
  • Jika suatu kategori berstatus Tidak ditemukan di tabel preview, artinya tidak ada folder dengan nama tersebut di dalam file KMZ sumber.
  • Pastikan minimal 1 kotak centang kategori aktif sebelum menekan Preview Pengurangan atau Download Hasil.

📖 Cara Penggunaan — Line Parser (Split Hasbel)

Pecah jalur kabel feeder panjang secara otomatis menjadi segmen-segmen per 1 hasbel (default 3.000 m efektif termasuk slack & spare), lengkap dengan peletakan titik Joint Closure (JC) dan titik Slack (per 400 m) yang menempel ke tiang terdekat.

🧭 Langkah-Langkah Penggunaan

1

Unggah KMZ / KML Jalur Feeder

Tarik & lepaskan file berisi jalur kabel (LineString) dan tiang, klik dropzone, atau klik Pakai KMZ dari Tab 1.

Sesuaikan Kapasitas 1 Hasbel (3000 m), Spare (5%), Panjang Slack (20 m), Interval Slack (400 m), dan centang opsi Snap ke Pole terdekat.

3

Proses & Preview Hasbel

Klik Proses & Preview Hasbel untuk melihat total hasbel, jumlah Joint Closure (JC), warna tiap segmen, chainage Start–End, tiang awal/akhir/JC, dan lokasi tiap titik slack.

4

Download KMZ/KML atau CSV

Pilih format .KMZ / .KML lalu klik Download KMZ/KML untuk visualisasi peta berwarna di Google Earth, atau klik Download CSV untuk rekap tabel hasbel.

⚙️ Penjelasan Parameter

  • Kapasitas 1 Hasbel (m) (default 3000 m): Batas maksimum panjang kabel efektif dalam 1 gulungan/drum hasbel.
  • Spare (%) (default 5%): Persentase cadangan kabel untuk kelonggaran tarikan/sagging antar tiang.
  • Panjang Slack (m) (default 20 m) & Interval Slack (m) (default 400 m): Penambahan cadangan gulungan slack di sepanjang jalur dan 1 slack ekstra di ujung/titik JC.
  • Snap titik potong (JC) & Slack ke Pole terdekat: Jika dicentang, sistem mencari tiang di sepanjang jalur (radius ≤ 10 m) sehingga pemotongan JC jatuh tepat di tiang terakhir sebelum melewati batas 1 hasbel, dan tiap titik Slack menempel pada tiang terdekat.

🧮 Rumus & Isi File Output

Jumlah Slack = ⌊Panjang Rute / Interval Slack⌋ + 1
Total (+Spare) = (Panjang Rute + (Jumlah Slack × Panjang Slack)) × (1 + Spare% / 100)
  • Output KMZ / KML: Setiap segmen hasbel diberi warna berbeda (Biru Langit, Hijau, Kuning, Oranye, Magenta, Ungu, Merah, Tosca) dilengkapi placemark titik Joint Closure (JC) dan Slack.
  • Output CSV: Berisi tabel lengkap nomor hasbel, chainage start–end, panjang rute, jumlah slack, total kabel efektif (+spare & pembulatan atas), pole awal, pole akhir/JC, serta daftar pole lokasi slack.

💡 Tips & Catatan Penting

  • Agar fitur Snap ke Pole bekerja optimal, pastikan file KMZ memuat folder tiang (Pole) yang posisinya berada dalam jarak ≤ 10 meter dari garis jalur kabel feeder.
  • Jika file hanya berisi garis rute tanpa titik pole (atau opsi Snap dimatikan), titik potong JC dan Slack tetap dihitung berdasarkan koordinat interpolasi chainage di sepanjang jalur.
  • Nilai panjang total efektif tiap hasbel selalu dijaga ≤ Kapasitas 1 Hasbel agar tidak ada tarikan yang kekurangan kabel di lapangan.
